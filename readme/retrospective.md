## 회고

### 1. 소감

이 클론 코딩을 하게 된 계기는 앞서 진행한 깃허브 클론 코딩이었습니다. 초보이다 보니 화면에 있는 요소를 하나하나 따라 만드는 일이 생각보다 어려웠고, 그래서 평소 즐겨 쓰는 서비스인 **네이버 웹툰**을 목표로 혼자 다시 클론 코딩을 해 보기로 했습니다.

이전에는 화면의 구성 요소를 덩어리로 나눠야 하는 이유를 몰라서, 요소를 무작정 쌓아 넣고 위치만 맞추는 식으로 작업했습니다. 그때 가장 어려웠던 점은 **어떤 요소끼리 묶어야 하는지** 이해하기 어려웠던 것이고, 공통 디자인 · 공통 요소의 존재를 놓쳐서 같은 작업을 여러 번 반복해야 했습니다.

이번에는 먼저 전체 화면을 **구역별로 나누고, 그 안을 다시 나누고, 또 나누는 방식**으로 정리한 뒤, 여러 곳에서 쓸 수 있는 공통 양식을 찾아냈습니다. 이 과정을 영역 분석표로 정리해 두니 HTML 구조와 CSS 배치를 미리 정할 수 있었고, 공통 컴포넌트(섹션 머리말, 필터, 포스터 카드, 배너)를 한 번 만들어 여러 섹션에 재사용할 수 있었습니다.

또 저작권 문제가 생길 수 있다는 다른 분의 경험을 듣고, 가능한 한 **생성형 AI로 이미지와 작품 정보를 가상으로 만들어** 사용했습니다. 이 페이지에서 네이버 웹툰 화면을 그대로 캡처해 가져온 것은 **QR 코드와 상단 로고뿐**입니다.

### 2. 트러블 슈팅

#### ① 원본에 없는 반응형을 Grid로 설계하기

- **문제**: 원본 네이버 웹툰 PC 화면은 Grid를 거의 쓰지 않는 것으로 보였고, 반응형도 없었습니다. 모바일은 별도의 앱 · 모바일 페이지로 따로 존재했습니다.
- **고민**: 다양한 화면 크기에 대응하는 레이아웃을 목표로 했기 때문에, 원본을 그대로 따라 하면 반응형을 보여줄 수 없었습니다.
- **해결**: 반응형을 직접 만들기로 하고, 화면 크기에 따라 배치가 바뀌어야 하는 곳(본문 · aside 2단, 이달의 신작, 베스트도전, 푸터)에 **Grid**를 사용하기로 결정했습니다. 표준 브레이크포인트(데스크톱 1024px 이상 · 태블릿 768~1023px · 모바일 767px 이하)에 맞춰, 구간마다 배치를 조금씩 수정해 비교적 보기 좋은 화면 구성을 완성했습니다.
  - 태블릿: aside를 본문 아래로 내리고 aside 안은 2열
  - 모바일: 1단 배치, 작품 목록은 손가락으로 넘기는 가로 스크롤
  - 데스크톱 안에서는 `clamp()`와 `auto-fit`으로 미디어 쿼리 없이 간격 · 열 수가 자동으로 줄어들도록 처리

#### ② 웹툰 바로가기 태그: 여러 개 중 원하는 것만 노출하기

- **문제**: 하단 웹툰 바로가기 태그는 여러 개를 두고, 노출하고 싶은 것만 보여주는 구조가 필요했습니다.
- **해결**: 숨길 태그의 `<li>`에 HTML 기본 속성인 **`hidden`** 을 넣어 구분했습니다. 지우면 다시 보이고, 스크린리더에서도 함께 숨겨집니다.
- **보완**: 나중에 다른 CSS가 `display`를 덮어써도 숨김이 풀리지 않도록 공통 CSS에 `[hidden] { display: none !important; }`를 추가했습니다.

#### ③ 이달의 신작: 캐릭터가 틀 밖으로 튀어나오는 입체감

- **문제**: 이미지가 틀 안에만 갇혀 있어서 원본처럼 입체적인 느낌이 나지 않았습니다.
- **해결**: 배경을 지운(누끼) 투명 PNG와 카드별 배경색을 이용했습니다.
  - 캐릭터를 틀 바닥에 붙이고 틀보다 크게 키운 뒤, `clip-path: inset(-40px 0 0 0)`로 **위쪽만 열어** 틀 밖으로 튀어나오게 했습니다.
  - `filter: drop-shadow`로 캐릭터 윤곽을 따라 그림자를 넣어 입체감을 살렸습니다.

#### ④ 캐러셀 버튼 배치

- **문제**: 다음 버튼을 포스터 세로 가운데에 맞추려면 목록마다 포스터 높이가 달라 위치를 따로 계산해야 했고, 화면이 좁아지면 버튼이 화면 밖으로 삐져나와 가로 스크롤이 생겼습니다.
- **해결**:
  - 포스터 높이를 CSS 변수(`--poster-h`)로 두고 `top: calc(var(--poster-h) / 2 - 20px)`로 계산해, 목록마다 값을 따로 쓰지 않아도 항상 가운데에 오도록 했습니다.
  - 버튼이 화면 양쪽 여백(16px) 안쪽에 걸치도록 `right` 값을 조정해 가로 스크롤을 없앴고, 모바일에서는 손가락으로 넘기므로 버튼을 숨겼습니다.
